# ЗАДАНИЕ для Claude Code — полное воспроизведение процесса создания обучающего датасета

**Статус цели:** сейчас процесс «сырьё → денойзинг → итоговый обучающий файл» воспроизводится
лишь *частично и приближённо* (шаг `00`, не побитово, и НЕ используется для обучения).
Задача — довести его до **полного, проверяемого воспроизведения**, чтобы обучающий датасет
можно было пересобрать из сырья и валидировать против выданного `SD…xlsx`.

> Прочитай сначала: `CLAUDE.md`, `docs/REPRODUCTION_NOTES.md` (особенно §5b),
> `docs/CRITICAL_REVIEW.md`. Не меняй модельный код без необходимости — фокус задания
> на data-preparation.

---

## 0. Контекст (что уже есть)

Цепочка-эталон (из статьи Makarov et al., Fuel 406 (2026) 136847):

```
Volve production data.xlsx (15635×24, 7 скважин, production+injection)
  → выбор 3 скважин (F-12, F-14 = train; F-11 = blind test), фильтр production
  → маппинг столбцов (лист abbreviation), OPR = BORE_OIL_VOL / ON_STREAM_HRS
  → дроп AVG_ANNULUS_PRESS (NM_3Apr 34 → NM_16Apr 31 столбец)
  → агрегация по дате: суммирование по активным скважинам (одна строка = дата)
  → очистка мёртвых забойных датчиков F-12
  → вейвлет-денойзинг (мягкий порог, адаптивный SURE)
  → нормализация min-max [0,1] (train/test раздельно)
  → NSGA-II/LSTM отбор фич 10 → 7
  → сплит по времени 75:25
  → SD28Nov2024_SelectedFeature_WeveletDenoised.xlsx  (Train 2176×8, Test 716×8)
```

Уже реализовано (приближённо):
- `src/raw_pipeline.py` — функции `load_raw`, `build_well_frame`, `clean_frame`,
  `aggregate_by_date`, `denoise_frame`, `compile_dataset`, `greedy_feature_selection`.
- `src/preprocessing.py` — `wavelet_denoise` (sym8, soft, `_sure_threshold`).
- `scripts/00_preprocess.py` — прогон + запись `results/preprocessing/recon_01..03.xlsx`
  и `results/tables/preprocess_fidelity.csv`.
- `scripts/00b_denoising.py` — характеристика двух режимов денойзинга.

Известные ограничения сейчас (их и нужно закрыть/задокументировать):
1. Денойзинг в обучении **не применяется** — `src/data.py` грузит готовый SD и только нормализует.
2. Реконструкция **не побитовая**: per-column Pearson 0.976–0.9999, но RMSE ненулевой
   (ADP≈20.6, OPR≈11.5 против SD).
3. Денойзинг-ряд совпадает по **режиму**, но не по значениям (recon lag-1≈0.96 vs SD≈0.905).
4. Точная импутация F-12, перекодировка `AW`, точные счётчики строк/окна дат — не восстановлены.

## 1. Цель

Сделать так, чтобы:
- (A) обучающий датасет можно было **пересобрать из `Volve production data.xlsx`** одной командой;
- (B) реконструкция **численно валидировалась** против выданного SD-файла с явными порогами;
- (C) пайплайн обучения мог по флагу конфигурации **обучаться на пересозданном датасете**
  и давать сопоставимые метрики;
- (D) всё, что объективно не восстановимо, было **явно задокументировано** с замером остаточного расхождения (никаких «молчаливых» приближений).

**Реалистичная планка:** побитовое совпадение может быть недостижимо без оригинальных
MATLAB-параметров. Целься в **максимальную верифицируемую близость** + честный отчёт об остатке,
а не в подгонку любой ценой.

## 2. Конкретные подзадачи

### 2.1. Формализовать истинную структуру SD (агрегация по дате)
- Подтвердить тестом, что SD = **посуточная сумма по активным скважинам**, а не стек скважин:
  `AW`∈{0,1,2,3} = число активных скважин; `OSH` до ~72.8; `OPR_mean`≈166.
- Добавить unit-тест `tests/test_aggregation.py`, проверяющий:
  - F-12 день 1: `BORE_OIL_VOL/ON_STREAM_HRS = 284.65/11.5 = 24.75`;
  - per-column `corr(recon_raw, SD) ≥ 0.97` для OSH/ADP/ADTemp/AWHP/DCS/OPR.

### 2.2. Денойзинг — добиться численного совпадения режима
- Параметризовать `wavelet_denoise`: семейство (`sym4/sym8/db4/db6/coif`), уровень,
  правило порога (`rigrsure`/`sqtwolog`/`heursure`/`minimaxi`), масштаб шума.
- Подобрать параметры так, чтобы денойзенный OPR воспроизводил характеристики SD:
  целевой **lag-1 autocorr ≈ 0.905** и **σ**, и максимизировал `corr` с SD-OPR
  (выравнивание по голове F-12).
- Записать выбранные параметры в `src/config.py` (единый источник истины), без хардкода в модулях.
- Acceptance: `corr(denoise(recon_raw_OPR), SD_OPR) ≥ 0.98` на совмещённом отрезке.

### 2.3. Очистка / импутация
- Подтвердить замером, что для воспроизведения SD импутацию мёртвых датчиков делать **не нужно**
  (`clean=False` даёт лучший corr). Зафиксировать тестом, что включение импутации **ухудшает**
  corr по ADP/ADTemp — чтобы решение было обоснованным, а не случайным.

### 2.4. Перекодировка `AW`
- Реализовать обе версии и выбрать по совпадению с SD:
  - `AW_count` = число активных скважин в день (ожидаемо совпадает с SD {0,1,2,3});
  - `AW_status` = 0/1 (как в тексте статьи).
- Документировать расхождение «текст статьи vs выданный файл» в `REPRODUCTION_NOTES.md`.

### 2.5. Отбор фич 10 → 7
- Прогнать `greedy_feature_selection` (и/или NSGA-II из `src/optimizers/nsga2.py`) на
  денойзенных агрегированных данных. Acceptance: **множество** из 7 отобранных фич
  = `{ADTemp, AW, Time, AWHP, DCS, ADP, OSH}`, выброшены ровно `{ADT, AWHT, ACS}`
  (порядок добавления может отличаться).

### 2.6. Сплит и запись итогового файла
- Время-упорядоченный сплит 2176/716 → листы `Train`/`Test`.
- Записать `results/preprocessing/recon_SD.xlsx` со столбцами `[Time, OSH, ADP, ADTemp, AWHP, DCS, AW, OPR]`
  в том же порядке, что в выданном SD.

### 2.7. Валидационная обвязка (главный артефакт верификации)
- `scripts/00c_validate_reconstruction.py`: считает per-column Pearson r + RMSE
  (recon vs SD, для Train и Test), пишет `results/tables/reconstruction_fidelity.csv`
  и печатает PASS/FAIL по порогам:
  - corr ≥ 0.97 по всем общим столбцам — обязательно;
  - corr ≥ 0.98 по OPR — целевое.
- Тест падает (exit code ≠ 0), если пороги не достигнуты.

### 2.8. Подключить к обучению (опционально по флагу)
- В `src/config.py` добавить `DATASET_SOURCE = "supplied" | "reconstructed"`.
- `src/data.py:build_dataset` при `"reconstructed"` грузит `recon_SD.xlsx` вместо выданного.
- Прогнать `run_all.py` на обоих источниках, сравнить Table 3/4 метрики, записать дельту
  в `results/tables/supplied_vs_reconstructed_metrics.csv`.

## 4. Ограничения / правила

- Один источник конфигурации — `src/config.py`. Не дублируй параметры по модулям.
- Детерминизм: сиды через `src.models.set_seed`. Не ломай его.
- Не коммить крупные артефакты (`*.xlsx` в results/, `*.pt`, `*.npz`) — они регенерируемы.
- Сырьё в `input data/` — read-only.
- Если шаг объективно невосстановим (нет авторских параметров) — НЕ имитируй совпадение;
  зафиксируй максимально достижимую близость и опиши причину.

## 5. Честная оговорка для исполнителя

Полное **побитовое** совпадение с выданным SD, скорее всего, недостижимо: точные ad-hoc
правки автора, оригинальный SURE-порог и параметры MATLAB-вейвлета неизвестны, а сам SD —
промежуточный файл с внутренними несостыковками (`AW`∈{0,1,2,3} против 0/1; `OSH`>24;
std тестового OPR в Table 4 ≈48 против ≈21 в файле). Поэтому «полный объём» здесь означает:
**весь процесс реализован, запускается из сырья, и его близость к SD измерена и задокументирована**,
а не «recon == SD до последнего знака». Любое заявление о точности должно подкрепляться числом из
`reconstruction_fidelity.csv`.
